# internal/inference/yolo — детекция лошади YOLO ONNX + кропы

## Детектор лошадей

Предобученный COCO-детектор выделяет лошадей в прямоугольные рамки (класс `horse` = 17). Движок поддерживает YOLO26x и YOLOv8n. Для предзаполнения карточки `ExtractTraits` измеряет характеристики по кропам, пользователь подтверждает результат.

## Пайплайн

1. Декод изображения (BlobStore по sha256 или Reader).
2. Letterbox 640x640 (серый 114, пропорции сохранены), NCHW 1x3x640x640, 0..1.
3. ONNX Runtime принимает тензор `images` и возвращает `output0` размером 1×300×6 у YOLO26x или 1×84×8400 у YOLOv8n.
4. Фильтр класса 17 и порог confidence 0,25. Для YOLOv8n применяется NMS с порогом IoU 0,45, для YOLO26x удаляются совпадающие рамки.
5. Мультивидные лошади: самая уверенная детекция → кропы:
   - корпус: bbox ±5%;
   - голова/морда: верхние 30% bbox, центральные 60% по ширине.
6. Кропы → `TraitDelegate` (по умолчанию — гистограммная эвристика по
   областям: голова/корпус отдельно, аналог ReferenceEngine).
7. Результат содержит версию детектора (`yolo26x-coco-v1` или `yolov8n-coco-v1`), уверенность и признаки.

## YOLO26x и проверка скорости

Новая установка настольной ноды использует YOLO26x. Если установлен только YOLOv8n, нода продолжает использовать его. Для явного выбора детектора укажите путь в `INFER_MODEL_PATH`. Менеджер моделей проверяет SHA-256 при установке. [Официальный YOLO26x ONNX](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26x.onnx).

Для сравнения скорости из каталога `backend` задайте `YOLO_MODEL_PATH`, `YOLO_RUNTIME_LIB` и `YOLO_BENCH_PHOTOS` абсолютными путями к весам, библиотеке ONNX Runtime и каталогу JPEG.
Команда `go test ./internal/inference/yolo -run '^$' -bench '^BenchmarkDetector$' -benchtime=30x -count=1 -v` измеряет подготовку входа, инференс и обработку рамок после трёх прогревочных кадров. JPEG декодируются заранее.

## Эмбеддинг отдельной лошади

При заданном `INFER_REID_MODEL_DIR` MegaDescriptor-L-384 получает прямоугольный RGB-кроп лошади из исходной фотографии, масштабированный до 384×384. Запросы и эталоны используют одинаковую обработку и нормированный вектор из 1536 координат версии `megadescriptor-l384-visual-v1`.

Для эмбеддинга нужен файл `megadescriptor-l-384.bin` или его проверенный экспорт `megadescriptor-l-384.onnx`. При пустой настройке действует 64-мерный RGB-вектор. Сохранённые силуэтные эмбеддинги используют отдельную версию дескриптора.

`EmbedInstances` обрабатывает все рамки или одну рамку оператора. Для аннотаций DINOv2 использует `dinov2-small.onnx` и `part-heads.f32`. Если измерения недоступны, в JSONL сохраняются рамка, эмбеддинг и причина ошибки измерений.

`traits.values` содержит исходные числа для видимых участков. Яркость шерсти и щеки — медианы яркости в диапазоне 0…1, теплота окраски — медиана (R − B) / (R + G + B), контраст морды — разность 75-го процентиля яркости морды и медианы яркости щеки, пропорции головы — отношение поперечного разброса к продольному. Для недоступного измерения ключ отсутствует. Флаг `-masks` включает маску частей тела и подсветку участков измерений.

Из каталога `backend` можно выгрузить эмбеддинги на этой машине.

```sh
go run ./internal/inference/cmd/horse-embed \
  -models ../infra/models/reid-v1 -detector ../infra/models/yolo26x.onnx \
  -runtime ../infra/models/libonnxruntime.1.32.0.dylib ../photos/pair.jpg
```

Команда пишет JSONL в stdout. `-gallery архив.jsonl` добавляет до пяти ближайших архивных кропов с других фотографий к каждой детекции. `-box x0,y0,x1,y1` задаёт рамку для одного фото в координатах декодированного изображения. Поле `source` отличает автоматическую детекцию, ручную рамку и пропуск. HTTP-поиск `/inference/similar` использует fingerprint подтверждённых признаков.

## Конфиг

```yaml
inference:
  engine: yolo
  model_path: infra/models/yolo26x.onnx
  runtime_lib: infra/models/libonnxruntime.so.1.31.1
```

Веса — вне git: `infra/scripts/download-yolo-model.sh` (sha256 проверяется).
Библиотека onnxruntime — NuGet `Microsoft.ML.OnnxRuntime` 1.31.1
(GitHub-релизы onnxruntime недоступны с 2026-11-17).

Если веса/библиотека недоступны — `inference.ErrModelUnavailable`, приложение
продолжает работать (ADR-0012: человек вводит признаки сам). Нет лошади на
фото — `inference.ErrNoAnimalDetected` → REST 400 «введите признаки вручную».

## Замена трейт-движка

`TraitDelegate` — точка расширения: будущий движок, обученный на лошадях
Пржевальского, реализует интерфейс и подменяет гистограммную эвристику без
изменения детекции. Смена весов — константа `ModelVersion`.

## Встроенные веса масок

Файл `part-heads.f32` содержит четыре линейных классификатора для признаков DINOv2-small. Порядок каналов — силуэт, голова, уши, морда. Каждый классификатор использует 384 признака, координаты патча и свободный коэффициент. Файл занимает 6 192 байта. Его SHA-256 — `17766f17e8a6b8fb6741b47fbc67f25c90e097043609b2891e57b3ad82d6a92d`. Журнал принимает и прежний экспорт с SHA-256 `a1f535819545891bd7ee01391575a9c02cdcc599da8dbf19425a980957254408`.

Для обучения использованы изображения PASCAL VOC с ручной разметкой PASCAL-Part. В выборку вошли 426 снимков за 2008–2010 годы из списка `VOC2012/ImageSets/Main/horse_trainval.txt` с меткой 1 или 0 и соответствующей аннотацией. Особи с шириной или высотой рамки меньше 32 пикселей исключены. Разбиение выполнено по идентификатору снимка до получения кропов и зеркальных отражений. Обучающая выборка содержит 460 лошадей на 314 снимках, проверочная — 141 лошадь на 106 снимках. [PASCAL VOC](https://www.robots.ox.ac.uk/~vgg/projects/pascal/VOC/voc2010/index.html) · [PASCAL-Part, Chen et al.](https://roozbehm.info/pascal-parts/pascal-parts.html)

Проверка выполнялась в Go через `horse-embed -mask-boxes` с эталонной рамкой лошади. Область головы для второго прохода выбирала сама модель. Отношение суммарной площади пересечения к площади объединения (IoU) для силуэта составило 0,7477, для головы — 0,7168, для ушей — 0,3621, для морды — 0,6898. Эти показатели относятся к PASCAL-Part. Качество на лошадях Пржевальского требует отдельной размеченной выборки.

Обучение можно повторить из корня репозитория. В каталоге `images` должны лежать выбранные JPEG, в `annotations` — одноимённые MAT, в `models` — проверенный `dinov2-small.onnx`. Скрипт записывает `models/part-heads.f32`. Использованные версии — NumPy 2.2.6, SciPy 1.15.3, Pillow 11.3.0 и ONNX Runtime 1.23.2.

```sh
python3 infra/scripts/train-horse-part-heads.py --images images --annotations annotations --models models
(cd backend && go build -o ../horse-embed ./internal/inference/cmd/horse-embed)
python3 infra/scripts/train-horse-part-heads.py --images images --annotations annotations --models models \
    --evaluate ./horse-embed --runtime "$INFER_RUNTIME_LIB"
```
