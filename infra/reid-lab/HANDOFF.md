# Re-ID лошадей Пржевальского: голова + тело + ArcFace — handoff

Документ для следующего исполнителя (человека или агента). Цель: **поднять качество распознавания особей**
на честном протоколе и встроить лучший вариант в существующий Go/ONNX-инференс (`backend/internal/inference`).
Всё ниже проверено руками, если не помечено «гипотеза».

---

## 1. Задача (кейс 03 «Заповедного хакатона»)

- Оренбургский заповедник, 140+ лошадей, 13 групп. Специалист фотографирует лошадь, сервис выдаёт **top-k кандидатов
  с процентом уверенности**, специалист подтверждает в один клик, подтверждённое фото пополняет фотобанк.
- Данные кейса: фотобанк на **15 особей** (`Фотобанк_Хакатон/<Кличка> (N фото)/`), паспорта, племенная книга.
- Требования организаторов, которые прямо влияют на ML:
  - валидация с **разбиением по датам съёмки**, а не случайно (иначе точность завышена);
  - **сезонность** (зимняя шерсть прячет полосы на ногах и тавро);
  - **несимметричность отметин**: левый и правый бок — разные эталоны, автоматическое определение ракурса;
  - подтверждённые кадры пополняют выборку.
- Продуктовые ограничения команды: работа **офлайн на обычном ноутбуке без GPU** (поле без связи), позже — телефон.

## 2. Данные

| Что | Где |
|---|---|
| Оригиналы фотобанка (JPG + немного CR2/NEF) | `https://data.yc-hack-horses.cu3rd.ru/extracted/Фотобанк_Хакатон/` |
| Паспорта / племкнига | там же, `extracted/Паспорта животных/`, `extracted/Племенная Книга/` |
| Доп. фото других особей из Telegram (размечены по папкам уверенности) | у команды: `horse_dataset/1_точно_одна_лошадь`, `2_кличка_точно_но_в_кадре_несколько`, `3_кличка_под_вопросом`, `4_лошади_без_клички` (~6.5k фото, ~30 кличек) |

Статистика фотобанка кейса: **1361 JPG**, 15 лошадей (59–172 фото на лошадь), даты 2016–2026,
**136 съёмочных сессий** (лошадь+день), 5–13 разных месяцев на лошадь, 5 фото без даты (исключаются).
RAW (CR2/NEF) сейчас пропускаются.

## 3. Текущий пайплайн (файлы в этой папке)

```
prep.py        фотобанк -> img/<id>.jpg (1280px, EXIF-ориентация) + meta.csv (id, horse, date из EXIF, src)
detect.py      YOLO11s (класс horse, самая крупная) -> ViTPose+ (AP-10K) -> crops/body, crops/head, det.jsonl (bbox, kps, view)
embed_local.py эмбеддинги body/head(/full): miewid | mega-l | dinov3      -> emb_<model>.npz
embed.py       то же для dinov2 | mega-t | mega-l (timm)                    -> emb_<model>.npz
train_head.py  ОСНОВНОЙ бенчмарк: StratifiedGroupKFold + ArcFace-проекция, печатает таблицу метрик -> cv_<model>*.json
evaluate.py    старый leave-same-day-out бенчмарк без обучения (оставлен для сравнения)
make_vlm_bench.py, score_bench.py   слепой тест VLM-агента против эмбеддингов (30 запросов)
sheet.py, posetest.py               контрольные коллажи боксов/ключевых точек (смотреть глазами!)
```

Запуск (CPU, ~1–2 ч на весь банк на ноутбуке; на 8-ядерном Xeon детекция ~13 фото/мин):
```bash
pip install -r requirements.txt
HORSE_BANK=/path/to/Фотобанк_Хакатон python prep.py 6
python detect.py                       # возобновляемый; DET_FROM/DET_TO/DET_OUT делят диапазон id между машинами
THREADS=12 python embed_local.py miewid
python train_head.py miewid --side     # таблица метрик
```

### Детали, которые легко сломать
- **ViTPose+ AP-10K**: `VitPoseForPoseEstimation.from_pretrained("usyd-community/vitpose-plus-base")`, `dataset_index=3`.
  `config.id2label` показывает **человеческие COCO-имена — это вводит в заблуждение**. Проверено глазами на коллаже:
  `0` нос, `1–2` глаза, `3–4` уши/затылок, `11–12` бёдра. Голова = квадрат вокруг точек {0..4} (score>0.3), ×1.6.
- **Бок**: нос левее средней точки бёдер на `0.25·ширина_бокса` → виден **левый** бок; правее → **правый**; иначе `front`;
  нет носа, есть бёдра → `rear`. Итог по банку: right 593, left 566, unknown 164, rear 22, front 16.
- **YOLO-World "horse head" не работает** — возвращает всю лошадь. Не тратить время.
- **MiewID**: remote-code репозитория ломается на transformers 5 (`all_tied_weights_keys`). В `embed_local.py` модель
  пересобрана вручную: `timm efficientnetv2_rw_m` + GeM(p=3) + `BatchNorm1d(2152)`, веса из `model.safetensors`
  (ключи `final.*` игнорируются). Вход 440×440, ImageNet-нормализация. ~0.5 с/кадр на CPU.
- Несколько лошадей в кадре: берётся **самая крупная** — источник шума в метках (особенно папки «в кадре несколько»).
- Windows: писать json с `encoding="utf-8"`, печатать с `PYTHONIOENCODING=utf-8` (клички кириллицей).
- На удалённых машинах не убивать процессы через `pkill -f "python detect.py"` из `ssh '...'` — паттерн совпадает
  с командной строкой самого ssh-шелла и рвёт сессию. Убивать по PID.

## 4. Протокол оценки (обязателен для всех сравнений)

- `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)`; **y = лошадь, group = лошадь|дата**.
  Assert в коде: ни одна сессия не попадает и в train, и в test.
- Галерея = train-фолд, запросы = test-фолд. Счёт лошади = **max косинуса** по её фото в галерее.
- Метрики: **top-1, top-3, macro top-1** (среднее по лошадям — классы несбалансированы 59…172), std top-1 по фолдам,
  top-1 по сезонам. Случайный уровень: top-1 6.7%, top-3 20%.
- Любое улучшение сравнивать **на тех же фолдах** с `raw` (замороженные эмбеддинги) — `train_head.py` печатает оба.

## 5. Результаты (MiewID-msv3, 1356 фото, 136 сессий)

| Вариант | top-1 | top-3 | macro top-1 |
|---|---|---|---|
| raw, тело | 22.8% | 44.4% | 20.2% |
| raw, голова | 23.2% | 45.3% | 21.4% |
| raw, голова+тело | 27.4% | 48.7% | 24.6% |
| ArcFace, тело | 26.2% | 51.6% | 23.2% |
| ArcFace, голова | 31.1% | 54.5% | 29.2% |
| **ArcFace, голова+тело** | **33.9%** | **57.6%** | **31.9%** |
| ArcFace, голова+тело, `--side` | 33.9% | 58.5% | 31.7% |
| ArcFace, голова+тело, `--side --season 0.03 --age 0.01` | 32.9% | 57.6% | 30.2% |

std top-1 по фолдам 6–10 п.п. Сезоны (лучший вариант): зима ~56%, лето ~42%, весна ~30%, осень ~28%.
ArcFace-голова: `Dropout(0.2) → Linear(2152→256)`, ArcFace s=30 m=0.3, веса классов 1/частота, AdamW 2e-3, 80 эпох,
шум 0.02 на признаки. Слияние `0.5·голова + 0.5·тело`, при отсутствии части — оставшаяся.
Сырые json: `results/cv_miewid*.json` (включают per-horse и per-season).

**Выводы**
1. Голова информативнее тела; вместе лучше всего. Раздельные эмбеддинги частей — правильное направление.
2. Дообучение даёт +6.5 п.п. даже как линейный слой поверх замороженной сети → **главный рычаг — нормальный fine-tune**.
3. Фильтр «тот же бок» сейчас ≈ 0 эффекта; ручные бонусы сезона/штраф возраста — 0 или минус (веса не подбирались;
   для raw-косинусов масштаб бонуса явно велик).

### Слепой тест VLM (для справки, не продолжать как идентификатор)
30 запросов (2 на лошадь из её последней сессии), галерея — 6 более ранних фото на лошадь коллажами.
`results/vlm_bench_key.json`, `results/vlm_bench_sonnet_answers.json`.

| | top-1 | top-3 |
|---|---|---|
| Claude Sonnet-агент (3 агента × 10 запросов) | 23% | 57% |
| MiewID raw, те же 6 фото | 10% | 33% |
| MiewID raw, все ранние фото | 23% | 47% |

Sonnet опирается на грубые признаки (окрас, чёрные ноги), уверенность 0.15–0.3, тянется к «типовым» лошадям
(Беркут 6 раз первым, 0 попаданий), ~40 с на запрос, нужен интернет. Годится максимум для текстовых объяснений.

## 6. Что делать дальше (по убыванию ожидаемой отдачи)

Каждый пункт — отдельный эксперимент с записью в таблицу из §5 на тех же фолдах.

1. **Fine-tune бэкбона end-to-end (GPU).** MiewID (или MegaDescriptor-L-384) + ArcFace/sub-center ArcFace (k=2–3:
   «летняя/зимняя» шерсть), PK-сэмплер (P=8–15 лошадей × K=4), отдельно голова и тело или одна сеть с эмбеддингом части.
   Аугментации: ColorJitter, RandomResizedCrop(0.6–1), blur, лёгкий поворот; **без HorizontalFlip** (бока разные;
   допустимо только как flip+смена метки бока, и только если бок используется явно). LR бэкбона 1e-5…3e-5, головы 1e-3.
   В репо есть `infra/datasphere` — вероятно, путь к GPU. Обучать **внутри фолдов** (5 моделей) или хотя бы на 4/5 с
   тем же сплитом; финальную модель — на всех данных.
2. **Больше особей в train.** Подмешать `horse_dataset/1_точно_одна_лошадь` (+ «кличка точно, несколько в кадре»
   с кропом нужной лошади) только в обучение; оценка — по-прежнему на 15 лошадях кейса. Проверить пересечение кличек с
   15 тестовыми (если те же лошади — следить за утечкой по датам).
3. **Голова в высоком разрешении.** Сейчас режется из 1280px-копии → мелкие завитки/маска теряются. Резать из оригинала
   (координаты масштабировать), вход головы 384–448px.
4. **Агрегация по серии.** Встреча = несколько кадров подряд. Усреднять (или max) счёт лошадей по кадрам одной сессии
   запроса; мерить отдельно «1 фото» и «серия». Дёшево и, вероятно, крупный прирост для продукта.
5. **Переранжирование top-5 локальными признаками** (ALIKED/SuperPoint + LightGlue, идея WildFusion): число инлайеров
   между запросом и лучшими фото кандидата, калиброванно смешать с косинусом.
6. **Калибровка уверенности + open-set.** Температура softmax по счётам (подбор на валидации, метрика ECE), порог
   «неизвестная лошадь / переснимите». Проценты в UI должны что-то значить.
7. **Бок/сезон/возраст — только обучаемо.** Вместо ручных бонусов: логистическая регрессия поверх признаков пары
   (cos_head, cos_body, same_side, same_season, |Δгод|), обучение на train-фолдах.
8. **Качество разметки.** Проверить/выкинуть кадры, где самая крупная лошадь — не та, что в имени папки
   (особенно многолошадные кадры): сделать коллажи `sheet.py` по каждой лошади и посмотреть.

**Не делать:** VLM как идентификатор; сравнение готовых моделей без дообучения как самоцель; ручной подбор весов
сезона/возраста на тест-фолдах (утечка).

## 7. Интеграция в продукт

- Прод-инференс — Go + onnxruntime: `backend/internal/inference/` (`reid/` — MegaDescriptor + части через
  DINOv2-small part-heads, `yolo/` — детектор; CLI `horse-embed` → `horse-rank` с `gallery.json`).
  Обучающий скрипт текущих part-heads: `infra/scripts/train-horse-part-heads.py`.
- Чтобы встроить результат: экспортировать **итоговую сеть эмбеддингов (бэкбон + проекция) в ONNX** для головы и тела,
  ключевые точки — ViTPose+ в ONNX (или заменить вырезку головы на уже существующую маску `head` из part-heads —
  сравнить качество вырезок!), хранить в галерее два вектора на фото + `view` + дату.
- Контракт `InferenceEngine` (README в `backend/internal/inference`) менять не нужно: добавляется реализация.
- Бюджет на ноутбуке без GPU: сейчас ~2 с на фото на весь пайплайн (YOLO11s 0.3 + ViTPose 0.7 + MiewID 2×0.5).

## 8. Определение «готово» для следующего шага

- Таблица §5 дополнена строками новых вариантов на **том же** протоколе (5 фолдов, группы лошадь|дата), с macro top-1
  и разбивкой по сезонам; цель — top-1 ≥ 50%, top-3 ≥ 75% (гипотеза, ориентир).
- Лучший вариант экспортирован в ONNX и проверен на совпадение эмбеддингов с PyTorch (cos > 0.999).
- Время инференса на CPU замерено и записано.
