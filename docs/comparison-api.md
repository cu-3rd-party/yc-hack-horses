# Сравнение полевого снимка

Предлагаемый контракт локальной ноды для Electron. Примеры используют короткие ID для читаемости. Текущая нода поддерживает загрузку и чтение файлов, каталог и базовую историю. Новые операции сравнения описаны для реализации бэкендом. Типы запросов и ответов находятся в `packages/contracts/src/comparison.ts`. Пути ниже начинаются с `/api/v1`.

## Анализ

1. `POST /blobs` с `multipart/form-data`, поле `file` содержит байты оригинала. При первой загрузке нода отвечает 201, при повторной — 200. Клиент использует `sha256` из ответа. Получить оригинал можно через `GET /blobs/{sha256}`.
2. `POST /comparisons` принимает, например, `{"blob_sha256":"<sha256>","top_k":5}`. По умолчанию запрашиваем до пяти разных особей на каждую найденную лошадь.
3. Когда анализ готов, ответ 201 содержит общий снимок и все детекции. Индексы на экране начинаются с единицы, решения адресуются по стабильному `detection_id`.

```json
{
  "comparison_id": "cmp_42",
  "blob_sha256": "<sha256>",
  "detections": [{
    "detection_id": "d_1",
    "detection_confidence": 0.98,
    "annotation": {
      "horse_polygon": [[0.1,0.24],[0.42,0.31],[0.38,0.79],[0.14,0.75]],
      "traits": [{"key":"muzzle","value":"light","polygon":[[0.10,0.35],[0.15,0.33],[0.11,0.41]]}]
    },
    "candidates": [{"horse_id":"h_7","name":"Сарана","cosine_similarity":0.91,"best_photo_id":"p_18"}]
  }]
}
```

Координаты — доли ширины и высоты оригинала от левого верхнего угла после применения ориентации фото. Полигон содержит минимум три точки по порядку обхода и замыкается при отрисовке. Число точек зависит от формы. Каждая черта хранит значение и собственный полигон или `null`, если положение неизвестно.

Для каждой детекции список особей отсортирован по максимальному косинусному сходству с одним из эталонов этой особи. Диапазон от −1 до 1. `best_photo_id` указывает на этот эталон в истории особи. `detection_confidence` относится к обнаружению лошади. Пустой `detections` означает, что на снимке лошадей не обнаружено. При пустом `candidates` можно сохранить новую особь.

## История и выбор

`GET /observations?horse_id=h_7&include=photos,annotations` возвращает массив существующих записей наблюдений с дополнительными полями. Клиент открывает лучший эталон и даёт листать все фото. Один и тот же исходный файл может встречаться в наблюдениях разных лошадей со своей разметкой.

```json
[{
  "id":"obs_12","horse_id":"h_7","observed_at":"2026-11-20T09:14:00Z","observer_id":"field-3",
  "location":"У ручья","blob_ids":["<sha256>"],"name":"Сарана у ручья",
  "photos":[{
    "photo_id":"p_18","blob_sha256":"<sha256>","name":"Сарана в профиль.jpg",
    "angle":"Слева","framing":"Общий план","quality":"Хорошее",
    "annotation":{"horse_polygon":[[0.1,0.2],[0.7,0.3],[0.7,0.8]],"traits":[]}
  }]
}]
```

История поддерживает прежние записи только с `blob_ids`. Отсутствующая разметка соответствует `annotation: null`. Стрелки слева переключают детекцию и её кандидатов. Справа меняется только фото выбранного кандидата.

## Решение по детекции

`PUT /comparisons/cmp_42/detections/d_1/decision` принимает одно из двух тел.

| Действие | Тело |
| --- | --- |
| Существующая особь | `{"action":"match","horse_id":"h_7","observation_name":"На выпасе"}` |
| Новая особь | `{"action":"create_horse","horse_name":"Искра","observation_name":"У ручья"}` |

Успешный ответ содержит `{"observation_id":"obs_53","horse_id":"h_7","remaining_detection_ids":["d_2"]}`. Повтор того же решения возвращает ту же сохранённую запись. Попытка заменить уже принятое решение другим получает 409. Создание новой особи, наблюдения и привязка разметки одной лошади к оригиналу составляют одну операцию.

`POST /comparisons/cmp_42/cancel` без тела возвращает, например, `{"status":"cancelled","saved_observation_ids":["obs_53"],"skipped_detection_ids":["d_2"]}`. Уже подтверждённые наблюдения сохраняются.

В рабочем режиме клиент сообщает об отсутствующем маршруте сравнения (404/405) и недоступном обработчике или модели (501/503). Переключение на демонстрационные результаты выполняется пользователем в настройках.
